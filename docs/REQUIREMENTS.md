# 需求说明

产品名称：物业助手 Demo（wecom-qwen-assist）  
版本：1.0.0  
读者：面试官、二次开发、自己复述项目时对照

## 1. 背景与目标

物业客服里，业主从微信/企微进来，先由模型辅助分类和建单，明确要人时再交给坐席。本仓库把这条链路收成可本地打开的最小系统。

**要证明的事：**

1. 通道能进会话，不是只调一次模型 API。
2. 同一用户的回复串行处理，后到消息不插队。
3. 模型可以调用工单工具，且不编造不存在的单号。
4. 人工可以接管和交回，接管后模型不再回。
5. 没有云密钥时，Mock 仍能走完整路径。

**明确不做：**

- 企业微信官方 AES 解密与签名验签（只留 URL 验证和明文 JSON）
- 多项目路由、长期记忆、租约恢复
- 持久化数据库、登录鉴权、多坐席抢单
- 模型训练或评测集

## 2. 角色

| 角色 | 从哪进 | 能做什么 |
|------|--------|----------|
| 业主 | 左侧微信面板，或 `POST /wecom/callback` | 发报修/投诉/查询/转人工 |
| 坐席 | 右侧工作台 | 看会话、接管、人工回复、交回 AI、看工单 |
| 系统 | 后台 | 排队、调模型、执行工具、SSE 推界面 |

## 3. 功能需求

### FR-01 通道接入

- `GET /wecom/callback?echostr=` 原样返回，满足微信 URL 验证。
- `POST /wecom/callback` 接受 `FromUserName`/`from`/`userId` + `Content`/`content`。
- 页面发送走 `POST /api/customer/send`，与回调进入同一个 `ChatService`。

### FR-02 会话与排队

- 按 `userId` 建会话，保存消息：user / assistant / agent / system。
- 同一会话的 AI 处理串行。模式为 `AI` 或 `HUMAN`。

### FR-03 千问辅助

- 配置 `DASHSCOPE_API_KEY` 时走通义千问 OpenAI 兼容接口。
- 未配置时走 `MockLlmClient`。
- 系统提示约定：辅助人工，不编造工单号，转人工不承诺上门时间。
- 工具调用最多 3 轮。

### FR-04 工单工具

| 工具 | 作用 | 默认 |
|------|------|------|
| create_ticket | 创建投诉/报事 | 类型缺省「报事」，等级缺省「中」，状态「待受理」 |
| query_tickets | 按用户+关键词查 | 无结果返回「当前没有工单。」 |
| assign_ticket | 分派处理人 | 状态改为「处理中」 |
| close_ticket | 关单 | 状态「已关闭」，原因追加到详情 |

工单号格式：`T` + 自增数字，从 1001 起。

### FR-05 人工接管

- 业主消息含「转人工」「人工客服」「找人工」时，会话切到 `HUMAN`，系统回复「已为您转接…」，不再调模型。
- 坐席可 `takeover` / `release` / `reply`。
- `HUMAN` 模式下业主新消息只入座席侧，不触发 AI。

### FR-06 工作台

- 左：业主微信，可切换两个演示用户，带快捷句。
- 右：会话列表、当前对话、接管/交回、工单表。
- SSE `/api/events` 推 `session`、`ticket`，页面自动刷新。

## 4. 非功能

| 编号 | 要求 |
|------|------|
| NFR-01 | JDK 8，Spring Boot 2.7，一条命令能起 |
| NFR-02 | 不配密钥也能演示 |
| NFR-03 | 密钥只走环境变量，禁止提交 |
| NFR-04 | 进程退出数据清空（内存） |
| NFR-05 | 模型失败时给可执行提示，引导转人工 |
| NFR-06 | 核心路径有自动化测试 |

## 5. 验收标准

1. `mvn test` 通过。
2. `mvn spring-boot:run` 后打开 `http://localhost:8080`。
3. 点「报修」出现工单；点「转人工」后坐席能回复，业主侧看得到。
4. `GET /wecom/callback?echostr=ping` 返回 `ping`。
5. 未配 key 时页顶显示 Mock；配了 key 显示真实模型名。
